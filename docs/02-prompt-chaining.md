# 02 — Prompt Chaining

---

## Pattern นี้คืออะไร?

Prompt Chaining คือการแบ่งงานใหญ่เป็น **ขั้นตอนย่อยๆ ที่ต่อเนื่องกัน** แต่ละขั้นตอนรับ Input จากขั้นตอนก่อนหน้า ส่ง Output ไปยังขั้นตอนถัดไป

```
Input
  │
  ▼
[Step 1: Analyze] ──→ Output 1
  │
  ▼
[Step 2: Outline] ──→ Output 2
  │
  ▼
[Step 3: Draft] ────→ Output 3
  │
  ▼
[Step 4: Review] ───→ Final Output
```

แทนที่จะให้ LLM ทำทุกอย่างใน Prompt เดียว (ซึ่งมักลืมหรือทำไม่ดี) คุณแยกงานเป็นขั้นตอน แต่ละขั้นมี Focus เฉพาะของตัวเอง

---

## เมื่อไหร่ควรใช้

- งานที่มีลำดับขั้นตอนชัดเจน
- แต่ละขั้นต้องใช้คนละ Prompt หรือคนละ Model
- ต้องการตรวจสอบหรือแก้ไขผลลัพธ์ระหว่างทาง
- ต้องการควบคุมคุณภาพแต่ละขั้นแยกกัน

**ตัวอย่าง:** การเขียนบทความ
1. Research — หาข้อมูลที่เกี่ยวข้อง
2. Outline — วางโครงสร้าง
3. Draft — เขียนร่าง
4. Review — ตรวจสอบและแก้ไข

## เมื่อไหร่ไม่ควรใช้

- งานที่ถาม-ตอบครั้งเดียวจบ
- งานที่ Latency ต่ำเป็นสิ่งสำคัญ (แต่ละขั้นเพิ่มเวลา)
- งานที่ LLM ทำได้ดีอยู่แล้วในขั้นตอนเดียว

---

## ข้อดี

- **Debug ง่าย** — รู้ทันทีว่าขั้นตอนไหนพลาด
- **ควบคุมง่าย** — ปรับแต่ละขั้นแยกกัน
- **ใช้ Model ต่างกันได้** — ขั้นง่ายใช้ Model เล็ก ประหยัด
- **ตรวจสอบระหว่างทาง** — เพิ่ม Human Review ตรงกลางได้

## ข้อเสีย

- **Latency สูงขึ้น** — ต้องเรียก LLM หลายรอบ
- **Cost สูงขึ้น** — หลายขั้น = หลาย Token
- **Error Propagation** — ถ้าขั้นแรกผิด ขั้นต่อไปก็ผิดตาม
- **ออกแบบยากขึ้น** — ต้องแบ่งงานให้ถูก

---

## การทำงาน

```
User: "เขียนบทความเกี่ยวกับ AI Agents"

Step 1 — Research
  Prompt: "ค้นหาข้อมูลเกี่ยวกับ AI Agents ในปี 2025"
  Output: ข้อมูล 5 ข้อที่ควรกล่าวถึง

Step 2 — Outline
  Prompt: "จากข้อมูลนี้ สร้าง Outline บทความ"
  Output: โครงสร้าง 4 ส่วน

Step 3 — Draft
  Prompt: "เขียน Draft ตาม Outline นี้"
  Output: บทความร่าง 800 คำ

Step 4 — Review
  Prompt: "ตรวจสอบ Draft นี้ หาจุดที่ต้องแก้"
  Output: บทความที่แก้ไขแล้ว
```

---

## ตัวอย่างการประยุกต์ใช้

### 1. Customer Support Pipeline
```
Classify Issue → Search KB → Draft Response → Review Tone
```

### 2. Data Extraction
```
Read Document → Extract Fields → Validate Schema → Format Output
```

### 3. Code Generation
```
Parse Requirements → Design Architecture → Generate Code → Add Tests
```

---

## ข้อผิดพลาดที่พบบ่อย

1. **Chain ยาวเกินไป** — เกิน 5-6 ขั้นเริ่มควบคุมยาก
2. **แต่ละขั้นไม่ชัดเจน** — ถ้าไม่รู้ว่าขั้นนี้ต้องทำอะไร = LLM ก็ไม่รู้
3. **ไม่ตรวจสอบระหว่างทาง** — Chain ยาว = Error สะสม
4. **ใช้ Model เล็กเกินไป** — ขั้นที่ซับซ้อนต้องใช้ Model ใหญ่

---

## Safety และ Verification

- ตรวจสอบ Output ทุกขั้นก่อนส่งต่อ
- เพิ่ม Human Review ที่ขั้นวิกฤต
- มี Fallback เมื่อขั้นใดขั้นหนึ่งล้มเหลว
- Log ทุกขั้นตอนเพื่อ Debug

---

## สรุป

Prompt Chaining คือ Pattern พื้นฐานที่มีประโยชน์มากสำหรับงานที่มีลำดับขั้นตอนชัดเจน เริ่มต้นง่าย ปรับปรุงทีละขั้นได้ และ Debug สะดวก

**ข้อควรจำ:** เริ่มจาก 2-3 ขั้นก่อน ถ้าคุณภาพยังไม่พอ ค่อยเพิ่มขั้นตอน หรือใช้ Reflection เข้ามาช่วย
