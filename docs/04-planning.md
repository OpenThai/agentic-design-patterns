# 04 — Planning

---

## Pattern นี้คืออะไร?

Planning คือการให้ AI Agent **วางแผนก่อนลงมือทำ** — แตกงานใหญ่ออกเป็นขั้นตอนย่อย เรียงลำดับการทำงาน ระบุเครื่องมือที่ต้องใช้ และอาจปรับแผนเมื่อพบอุปสรรค

```
Input: "จัดทริปท่องเที่ยวญี่ปุ่น 7 วัน"
  │
  ▼
[Plan]
  ├─ 1. หาข้อมูลสถานที่ท่องเที่ยว (Search)
  ├─ 2. วางแผนเส้นทางแต่ละวัน (Analyze)
  ├─ 3. หาที่พัก (Search)
  ├─ 4. คำนวณงบประมาณ (Calculate)
  └─ 5. สรุปแผนการเดินทาง (Generate)
  │
  ▼
[Execute Step by Step]
  └─ ปรับแผนเมื่อเจออุปสรรค (เช่น ที่พักเต็ม → หาใหม่)
```

Planning ไม่ใช่แค่การแบ่งงาน — แต่รวมถึงการ **ประเมินทรัพยากร** **จัดลำดับความสำคัญ** และ **ปรับเปลี่ยนเมื่อสถานการณ์เปลี่ยน**

---

## เมื่อไหร่ควรใช้

- งานซับซ้อนที่มีหลายขั้นตอน
- งานที่ต้องใช้เครื่องมือหลายอย่าง
- งานที่ต้องปรับเปลี่ยนแผนระหว่างทาง
- งานที่มีลำดับการทำงานที่ไม่ตายตัว

**ตัวอย่าง:**
- วิจัยและเขียนรายงาน
- วางแผนการเดินทาง
- Data Analysis Pipeline
- Software Development Task

## เมื่อไหร่ไม่ควรใช้

- งานที่ลำดับขั้นตอนตายตัว (ใช้ Prompt Chaining ดีกว่า)
- งานง่ายๆ ที่ LLM ทำได้ในครั้งเดียว
- งานที่ Latency มีความสำคัญมาก
- ระบบที่ไม่ต้องปรับเปลี่ยนแผน

---

## ข้อดี

- **แก้ปัญหาซับซ้อนได้ดี** — แบ่งงานให้จัดการได้
- **ปรับตัวได้** — เปลี่ยนแผนเมื่อเจออุปสรรค
- **ใช้ Machine Power อย่างเหมาะสม** — รู้ว่างานไหนต้องใช้เครื่องมืออะไร
- **Transparent** — เห็นแผนก่อนลงมือทำ

## ข้อเสีย

- **Plan อาจผิด** — LLM วางแผนไม่ดี ทำให้เสียเวลา
- **กิน Token เยอะ** — Plan, Execute, Monitor หลายรอบ
- **Latency สูง** — ต้องคิดแผนก่อนทำงานจริง
- **Over-planning** — วางแผนละเอียดเกินความจำเป็น

---

## การทำงาน

### 1. Plan Creation
Agent วิเคราะห์งานและสร้างแผน:
```
Task: "วิเคราะห์ข้อมูลการขายและทำรายงาน"
Plan:
  Step 1: Query ข้อมูลจาก Database
  Step 2: วิเคราะห์แนวโน้มด้วย Statistical Tools
  Step 3: สร้าง Visualization
  Step 4: เขียนรายงานสรุป
  Step 5: ตรวจสอบรายงานก่อนส่ง
```

### 2. Plan Execution
รันทีละขั้น โดยอาจปรับเปลี่ยน:
```
Step 1 → ได้ข้อมูล
Step 2 → พบข้อมูลไม่เพียงพอ → ปรับแผน: Query เพิ่ม
           (Agent ตัดสินใจปรับแผนเอง)
Step 3 → สร้าง Chart สำเร็จ
...
```

### 3. Plan Review
ตรวจสอบว่าทำครบทุกขั้นและผลลัพธ์ถูกต้อง

---

## ข้อผิดพลาดที่พบบ่อย

1. **Plan ซับซ้อนเกินไป** — 20 ขั้นตอน แต่ทำจริงแค่ 3
2. **Plan ไม่ยืดหยุ่น** — ทำตามแผนเป๊ะๆ ไม่ยอมปรับเมื่อเจอปัญหา
3. **ไม่ตรวจสอบความคืบหน้า** — ทำ Step ถัดไปทั้งที่ Step ก่อนยังไม่เสร็จ
4. **Over-planning** — ใช้เวลาวางแผนมากกว่าทำงานจริง

---

## วิธีการ Planning แบบต่างๆ

| วิธี | คำอธิบาย | เหมาะกับ |
|---|---|---|
| Linear Plan | แผนเส้นตรง Step ต่อ Step | งานที่มีลำดับชัดเจน |
| Tree Plan | แตกเป็นกิ่งก้าน สาขาย่อย | งานที่มีหลายทางเลือก |
| Replan | วางแผนใหม่เมื่อเจออุปสรรค | งานที่คาดเดาไม่ได้ |
| Hierarchical Plan | แผนระดับสูง → แผนย่อย | งานที่ซับซ้อนมาก |

---

## Safety และ Verification

- ตรวจสอบแผนก่อน execute (อาจให้มนุษย์ approve)
- จำกัดจำนวนขั้นตอนสูงสุด (ป้องกัน infinite loop)
- Timeout สำหรับแต่ละขั้น
- Log การเปลี่ยนแปลงแผนทุกครั้ง
- มี Fallback เมื่อแผนล้มเหลว

---

## สรุป

Planning ช่วยให้ Agent จัดการงานซับซ้อนได้ดีขึ้น โดยการวางแผนก่อนลงมือและปรับเปลี่ยนเมื่อจำเป็น แต่ต้องระวัง Over-planning และ Plan ที่ผิดเพี้ยน

**ข้อควรจำ:** ใช้ Planning เฉพาะเมื่อจำเป็น — งานที่ลำดับตายตัวใช้ Prompt Chaining ดีกว่า
